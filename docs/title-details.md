# User-scoped title details (Seerr 3.4.1 / Jellyfin 12.1)

`GET /3picFin/TitleDetails?mediaType=movie|tv&mediaId=<positive TMDb ID>` requires one authenticated, existing `Jellyfin-UserId` claim. It performs one fresh Seerr user mapping and one mapped Seerr detail GET (`X-API-User`) under a shared ten-second deadline, bounded response bytes, and no catalog fetch. Errors return 403 (unmapped) or 502 (invalid/unavailable upstream), not upstream JSON. Responses are `private, no-store`.

The explicit PascalCase DTO is `Title`, `Overview`, `PosterPath` (safe relative poster path or null), `MediaType`, `TmdbId`, `MediaStatus` (Seerr's state, **not** proof of local playback), `LibraryItemId` (GUID when matched; omitted on the wire when null in the tested Jellyfin 12.1 serializer), `CanRequest`, `CanRequest4k`, `Seasons` (positive bounded TV season numbers), and `Date` (validated ISO calendar date or null). In the disposable v12.1 response, a matched `LibraryItemId` was **32 compact hexadecimal characters, not a hyphenated GUID**; the client accepts both exact forms. Request booleans describe the mapped user's Seerr permission and blocklist state independently of local playback: a local series may still lack requestable seasons. Seerr may reject already-requested or available variants. No paths, tokens, Seerr user details, or raw upstream object are returned.

`mediaInfo.jellyfinMediaId` is a hint only. The local resolver scans at most eight currently visible collection roots and 256 candidates per root (the 257th fails closed), with a type-specific user query. It independently requires exact TMDb provider ID and Movie/Series type, a unique match, nonvirtual item, standalone visibility of the item and every intermediate ancestor, and ancestry within the visible root. Before returning an ID, it re-reads the user's root membership and standalone visibility of the root, item, and every intermediate ancestor, along with the item's type, provider ID, and ancestry; a revocation during the scan fails closed. A supplied hint must agree with the verified match; malformed hints are ignored. Missing, ambiguous, over-budget, inaccessible, or mismatched matches yield `LibraryItemId: null`. The UI must navigate only when that ID is non-null; Seerr's `MediaStatus: 5` alone must never imply playback.

The bounded scan trades false negatives in large libraries for safe uniqueness. The pure resolver tests are complemented by `python tests/disposable-title-details.py --browser`: this builds a scratch-only DLL with lab index/Home bundle pins, installs disposable File Transformation/Plugin Pages/HSS dependencies, boots Jellyfin 12.1 with two disjoint movie/TV users and a loopback Seerr 3.4.1-shaped stub, and removes the containers, temporary configuration, tokens, and media on exit. The HTTP assertions cover own and foreign local matches, a rated-R intermediate folder hiding a child, a mismatched Seerr GUID hint, a local series with requestable remote seasons 1 and 2, anonymous 401, userless API key 403, wire casing/cache/secret allowlisting, and fresh mapping/detail read pairs. The signed-in Chromium pass clicks a rendered discovery card, opens the native Jellyfin details route only for a revalidated local match, keeps the Open button hidden for a restricted child despite Seerr status 5, and opens a TV request modal with two season choices. This proves the tested lab distribution and moment-in-time responses, **not** a dynamic revocation race or production Home compatibility; no production pins or credentials are used.
