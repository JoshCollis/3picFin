# Independent Home hero mode

`HomeEnabled` and `HeroTrustedFilesystemEnabled` must be on, with a nonempty, valid explicit `HeroLibraryIds` selection. `DiscoveryPageEnabled` may remain off. The existing Home adapter still requires an exact pinned web distribution and an exact index transform; the public production pins remain unset. The filesystem-writer trust decision and metadata image-route confinement remain mandatory. Neither the mode response nor web assets contain credentials or library inventory.

The signed-in, no-store `GET Rowan/Home/Mode` returns only `DiscoveryEnabled` and `HeroEnabled`. On a verified Home mount the host reads this mode before loading a fragment. With Discovery off it leaves native HSS sections in place, adds no 3pic Fin tab or Discovery HTML/JS/CSS, and mounts the hero above the sections only if the user-scoped slide route returns valid slides. With Discovery on it retains the Home/3pic Fin inner switch and defers Discovery data until selected. Favorites and native route ownership remain Jellyfin's. Route exit, logout, and identity switch tear down the host, hero blobs and styles; a remount reads the mode again.

The image endpoint still applies its own user, selected-root, ancestor-visibility, trusted-filesystem and confined metadata-file checks. The mode flag is a UI hint, never authorization for image retrieval. No production distribution pin or Gill configuration was changed.

Automated coverage: .NET flag/asset-gate tests and Node host tests for both modes, disabled mode, stale identity, remount transitions and Home/Fin switch. A separate signed-in disposable hero-only run returned `DiscoveryEnabled=false, HeroEnabled=true` from the no-store Mode endpoint, denied anonymous (401) and userless-key (403) callers, and automatically rendered a decoded metadata JPEG at 390px with no Discovery assets or Fin tab. Native Open, HSS cards, Favorites, logout teardown and a second-user remount passed. The first lab-only exact-index pin failed closed because the dependency-transformed index differed between configurations; pinning the observed hero-only origin response in scratch passed. This is neither a production pin nor full mobile/ElegantFin acceptance. Configuration changes on an already mounted Home route require remount.
