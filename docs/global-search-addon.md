# Native Search augmentation (Jellyfin 12.1)

> **Current implementation supersedes the staging notes below.** With `GlobalSearchEnabled`, File Transformation injects `global-search-addon.js` and `search-adapter.js` into the complete index, without a distribution hash. It mounts a separate, single-row horizontal "Available to request" rail visually after the first populated native results group on signed-in, unscoped 12.1.x `/search?query=...` or `#/search?query=...`, falling back near the input when there are no native groups. Native rows retain their DOM positions and React ownership; CSS `display: contents`/flex order controls only the visual sequence. The rail scrolls within each bounded Seerr page; its previous/next arrows advance pages at the ends. Each poster has one keyboard-accessible Details action overlaid inside it; a missing/broken poster keeps the same card geometry with a titled fallback. Details lazy-loads the existing Discovery details and request-options/modal/POST/read-back flow. Native Jellyfin cards lack complete TMDb identities, so **cross-section duplicates are possible**; only repeated catalog items are suppressed. Scoped filters fail closed. Tests: `python3 tests/Rowan.Jellyfin.Plugin.Tests/native-search.browser.py`, `python3 tests/Rowan.Jellyfin.Plugin.Tests/search-rail.browser.py`, `node --test tests/Rowan.Jellyfin.Plugin.Tests/global-search-addon.test.cjs`, and `dotnet test`. Set `ELEGANTFIN_CSS_DIR` to a local capture containing `elegant-source-0.css` and `elegant-source-1.css` for rendered theme checks; those third-party files are not redistributed. Synthetic browser proof is not stock or custom Jellyfin installation proof; verify separately before deployment.

## Historical staging notes (obsolete)

Pinned source reviewed: Jellyfin-web `fae41f33eb7cd636a9ef68984adb82bb247a6e1b`, `src/apps/legacy/routes/search.tsx` uses `/search?query=...` with a 500 ms debounced query, then mounts React `SearchResults` or suggestions inside `#searchPage`; `SearchResults.tsx` renders grouped native `useSearchItems` results. A plugin has no React extension point here. This slice does **not** transform native search, patch webpack or register a route. SeerrFin 1.7.1.2 internals were not independently verified in this slice; do not claim behavioral parity.

`global-search-addon.js` exposes `ThreePicFinSearchAddon.createSearchAddon()` (`module.exports` for tests). The future version-pinned host must load it once, own script/CSS lifetime, and explicitly call `mount({root, apiClient, userId, sessionUserId, query, parentId, collectionType, nativeTmdbKeys, requestAction, enabled, fingerprint})` on the global search route only. `parentId` and `collectionType` must each be explicitly `null` for unscoped search; missing or scoped values fail closed. The current `/3picFin/Search` endpoint is unscoped and must never be shown inside a library/collection-scoped native search. On a scope change call `update({parentId, collectionType})` (which tears down if either is scoped) or `dispose()`; do not re-enable until an unscoped host has independently validated its native identity set. This is a host contract only, not a built or verified scoped native search integration. `root` is the owned insertion container: the adapter appends one separate section and **never edits native descendants**. `apiClient` is authenticated Jellyfin ApiClient (`getUrl`, `getJSON`); `sessionUserId()` must read the *current* authenticated user, not a captured ID. `nativeTmdbKeys` is the complete current native identity set in `movie:TMDbId` / `tv:TMDbId` form; on native result changes call `update({nativeTmdbKeys})`, on debounced router query changes first dispose or wait for new native results, then call `mount` or `update({query, nativeTmdbKeys})` **atomically** with the newly resolved complete native set. A query-only update tears down; it may not reuse the prior query's set. Native identity extraction must be verified against the pinned distribution; absent a complete set the host must not mount (an empty set is valid only when native search has resolved to empty). Host must call `dispose()` on route change, user change, logout and unmount. If the current user changes before an async response or action, the adapter tears down without rendering or dispatching.

`requestAction(item, button)` must invoke the **existing Fin request-options/dialog/submit/read-back flow**, with the clicked button for focus restoration. The existing flow is private inside `discovery.js` today, so this callback cannot yet be wired without extracting it into a shared controller. Never implement a second request POST here or send a Seerr API key to the browser. The addon uses only the existing authenticated `/3picFin/Search` DTO, clamps displayed items/page count, and suppresses duplicates by TMDb identity (not title). Source errors leave native results untouched.

Both the server-side `GlobalSearchEnabled` asset gate and the exact distribution SHA-256 pin inside the adapter default to off/unset. Merely toggling the flag serves public static assets, not search integration. No production pin is part of this implementation.

## Pinned host findings and disposable acceptance gate

Official source at [`fae41f33`](https://github.com/jellyfin/jellyfin-web/tree/fae41f33eb7cd636a9ef68984adb82bb247a6e1b): [`search.tsx`](https://github.com/jellyfin/jellyfin-web/blob/fae41f33eb7cd636a9ef68984adb82bb247a6e1b/src/apps/legacy/routes/search.tsx) reads `parentId`, `collectionType`, `query` from URL and debounces the query 500 ms; without a debounced query it renders suggestions, otherwise `SearchResults`. [`SearchResults.tsx`](https://github.com/jellyfin/jellyfin-web/blob/fae41f33eb7cd636a9ef68984adb82bb247a6e1b/src/apps/legacy/features/search/components/SearchResults.tsx) waits for `useSearchItems`, renders a no-items message or `.searchResults` containing rows. [`SearchResultsRow.tsx`](https://github.com/jellyfin/jellyfin-web/blob/fae41f33eb7cd636a9ef68984adb82bb247a6e1b/src/apps/legacy/features/search/components/SearchResultsRow.tsx) builds cards imperatively in an effect through `cardBuilder.buildCards`; React's row render is **not** proof cards are complete. [`cardBuilder.js`](https://github.com/jellyfin/jellyfin-web/blob/fae41f33eb7cd636a9ef68984adb82bb247a6e1b/src/components/cardbuilder/cardBuilder.js#L988) puts Jellyfin `data-id` and `data-type` on a card but **not TMDb ProviderIds**. [`useSearchItems.ts`](https://github.com/jellyfin/jellyfin-web/blob/fae41f33eb7cd636a9ef68984adb82bb247a6e1b/src/apps/legacy/features/search/api/useSearchItems.ts) merges several queries including an 800-item typed query, then groups them. [`queryOptions.ts`](https://github.com/jellyfin/jellyfin-web/blob/fae41f33eb7cd636a9ef68984adb82bb247a6e1b/src/apps/legacy/features/search/constants/queryOptions.ts) does not explicitly request provider IDs. A DOM-only `data-id`/title match is not a TMDb identity proof; nor is replaying a different search API request necessarily the same rendered set. These are source facts, not a browser observation of the distributed bundle.

**Fail-closed host protocol:** after exact-distribution compatibility validation, identify a unique active `#searchPage`, unscoped URL and the current signed-in user. On each debounced query epoch invalidate/teardown the old addon *before* the next native result phase. Obtain the complete actually-rendered Movie/Series card set after native card effects settle (including the empty state); resolve each card's `data-id` under the same current user to a verified `ProviderIds.Tmdb` and expected native type, with explicit bounded count and failure policy. If any card lacks a verified identity, a card set changes during hydration, the 800-result cap obscures completeness, scope/user/route changes, or the host cannot prove native completion, **do not mount Seerr**; retain native results untouched. A per-card hydrated lookup must be authorized and bound to the captured user and query epoch. A batch/items response is only acceptable if verified against every rendered card, not as a replacement for them. Do not infer a zero-card result from a loading spinner or temporary empty container. Feed `movie:<positive TMDb integer>` / `tv:<positive TMDb integer>` atomically with the resolved query to the addon. A MutationObserver, if used, must ignore its own section and disconnect on teardown; mutations while awaiting hydration invalidate the snapshot. `parentId` or `collectionType` present in the URL, even empty, is conservatively scoped until explicitly classified in the disposable client.

**Request-action blocker:** `discovery.js` owns `openRequest`, `submitRequest`, its dialog and mutable generation/selection state within its private `mount`. Extract a single user-bound request controller (options, modal, submit, read-back and focus restore), used by both Fin cards and the search host. Its callback must recheck the current session and epoch on click, after options, before POST, and after read-back; teardown must invalidate old dialogs/buttons. A stale detached button cannot invoke a request merely because it was valid when rendered. Do not borrow the currently mounted Fin page DOM or duplicate POST logic.

**Disposable acceptance recipe (not yet executed):** run `node --test tests/Rowan.Jellyfin.Plugin.Tests/global-search-addon.test.cjs` for pure adapter behavior, then in an isolated Jellyfin-web 12.1 browser with fake Seerr and two disjoint users: (1) capture the *actual* index/search chunks, network responses and bundle hashes on base and subpath URLs, never copy lab hashes into production; (2) search a movie and series whose native and Seerr DTO identities overlap, plus Seerr-only titles, assert one native card remains and only Seerr-only sibling cards/actions appear; (3) hold old native hydration/Seerr fetch/options promises, change query/scope/user/logout/route, click retained old buttons, assert zero POSTs and no old-user content; (4) native loading, empty, 800-cap, missing ProviderIds and malformed item must each fail closed until a verified complete snapshot; (5) execute request options/dialog/TV seasons/submit/read-back through the shared controller, verify focus and no duplicate write on uncertain outcome; (6) repeat at narrow/wide keyboard widths in stock and ElegantFin dark/light, plus subpath `ApiClient.getUrl` requests. Assert asset gate off and null production pin continue to prevent automatic mounting. This is a test specification, **not** evidence of signed-in integration.
