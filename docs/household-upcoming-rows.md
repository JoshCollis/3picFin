# Household Upcoming Home data (staged)

From `adf0ba3`, this slice adds `GET Rowan/Home/Rows/UpcomingMovies` and `UpcomingShows`. `HomeEnabled`, `CalendarEnabled`, and the respective independent `UpcomingMoviesRowEnabled` / `UpcomingShowsRowEnabled` switches must all be true. All default off. The controller requires one valid, existing signed-in Jellyfin user; anonymous/userless keys fail before Arr access. Responses are `private, no-store`. The two optional `native-home-rows.js` rows load lazily and independently via `ApiClient.getUrl`; they are not automatically inserted into Jellyfin Home. The production Home bundle pin remains unset. Do not enable on a live server from this build.

The existing bounded Calendar client queries both sources concurrently with independent eight-second deadlines and source errors, a half-open 31-day UTC window, 128 KiB response cap, and first-100-record partial flag. This slice validates optional `monitored` as a JSON boolean; malformed values fail that source and missing values remain unknown. In pinned Radarr `v6.4.4.10685`, `src/Radarr.Api.V3/Movies/MovieResource.cs` declares nullable compatibility `HasFile` but `MovieResourceMapper.ToResource` does not assign it; it does assign `MovieFileId = model.MovieFileId`. `src/NzbDrone.Core/Movies/Movie.cs` defines `HasFile => MovieFileId > 0`. Accordingly Radarr `movieFileId=0` means no file, a positive bounded integer means file, missing means unknown, and null/negative/noninteger/out-of-range invalidates Radarr alone. The Radarr compatibility `hasFile` field is ignored even if contradictory. Sonarr independently validates its episode `hasFile` JSON boolean. The internal normalized file status and monitored value are not serialized in Calendar or row JSON. A row only admits `monitored=true`, normalized no-file status, a strictly future UTC date, and matching Arr type. Movies take the earliest future Cinema/Digital/Physical event per TMDb title, shows keep distinct Sonarr episodes with `airDateUtc`. At most 16 cards are returned per row. The DTO contains only type, external title ID, title, event kind/date, and episode labels/numbers—no path, media source, poster URL, token, requester, Jellyfin item ID or playback endpoint. Partial and error states remain explicit.

HSS 3.0.2 source at `d9798e4` (`UpcomingSectionBase`, `UpcomingMoviesSection`, `UpcomingShowsSection`) filters `Monitored && !HasFile`, sorts release/air dates, takes 16, and optionally filters by path-to-library matching. Its unmatched paths are admitted; we do not claim that as entitlement. We deliberately use explicit household disclosure instead of claiming per-library/parental visibility. HSS movie dates honor configurable release-type switches and a default three-month horizon; shows default to one week. This slice instead uses the existing Calendar 31-day window and earliest future movie event. It does not reproduce HSS posters, countdowns, navigation, timeframes, path matching, or Jellyfin playability. The Date field is an Arr event date, not a promise that Jellyfin has the media. Compare populated HSS and this staged row in a disposable signed-in browser before claiming presentation parity or replacing HSS.

Tests cover absent/malformed status, downloaded/unmonitored titles, deduplication, source isolation, claims and flags, admin pending-save snapshots, lazy subpath reads and no playback links. `dotnet test`, Node tests, and Release build are local gates; no live installation or browser parity gate was performed here.
