# Isolated still-image hero

## Trust and enablement

Both `HomeEnabled` and the separate `HeroTrustedFilesystemEnabled` admin setting must be true. Both default **off**. The configuration key retains its name for compatibility; it now asserts trust in Jellyfin's **internal metadata**, not all media files. With the hero gate off, `GET Rowan/Home/Hero` returns `[]` for a valid user and `GET Rowan/Home/Hero/Image/{itemId}` returns 404 for a valid user; authorization still applies. The image route only accepts files under `IServerApplicationPaths.InternalMetadataPath/library`; media/share image paths fail closed. Do not enable the trust setting on a live server until metadata ownership, mount targets and write access are audited. Atomic confinement rejects symlinks and nested mounts, but the checkbox still asserts a trusted metadata source: malicious in-place writers and hardlinks inside that filesystem remain outside its protection.

`GET Rowan/Home/Hero` is `[Authorize]`, requires exactly one valid existing `Jellyfin-UserId`, and has no caller-supplied user/library IDs. It derives visible top-level collection folders from that user, queries at most 20 folders and 20 latest Movie/Series candidates per folder, checks the parent and ancestry again after the query (Jellyfin's missing-parent fallback), and performs DTO conversion with visibility checks enabled. The result is at most 12 slides, deterministically shuffled per user per UTC day. It contains item IDs, title, overview, year and a Backdrop image identity only—no arbitrary image URLs, trailers, playback URLs, paths or user data. Libraries outside the first 20 visible folders are not considered.

## Image route and limitations

`GET Rowan/Home/Hero/Image/{itemId}?tag=<hex>` is `[Authorize]` and requires exactly one real, existing `Jellyfin-UserId`; userless API keys are rejected. Every request re-resolves the item under Jellyfin's user-aware visibility lookup, checks parental/standalone visibility and ancestry against the user's currently visible collection folders, restricts kind to Movie/Series, and validates the current local Backdrop/0 image tag. It does **not** use `IImageProcessor` or resize: on Linux x86-64/arm64 it opens the exact absolute metadata path with `openat2` relative to a descriptor for `InternalMetadataPath/library`, using `RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS|RESOLVE_NO_XDEV` on the candidate, then checks type/size on that descriptor with `statx(AT_EMPTY_PATH)`. It reads at most 8 MiB, checks JPEG markers and dimensions (at most 8,294,400 pixels), and serves JPEG bytes without a redirect or path disclosure. Admission is limited to four concurrent distinct users, four requests per user per second and 16 globally per second; async reads have a three-second deadline. Responses have `private, no-store` and `nosniff`. Unsupported kernels/architectures, nonlocal, oversized, mount-crossing or unsupported images fail closed. The kernel confinement removes pathname symlink-swap TOCTOU for this route; it does not defend against malicious hardlinks or in-place mutation by writers inside the metadata filesystem.

The client uses authorized `ApiClient.fetch`, makes a short-lived blob URL from a JPEG response, revokes it on slide changes/teardown and ignores late responses or session changes. It never requests `/Items/{id}/Images/*` itself. Tags are cache identity, not access grants. **Jellyfin's separate raw image API can return HTTP 200 anonymously by item ID on v12.1**; this proxy protects only its own route, not that upstream API. Item IDs are not secrets.

The standalone `static-hero.js`/`.css` assets remain embedded behind the disabled-by-default `DiscoveryPageEnabled` asset gate. The host must supply a dedicated empty root and signed-in `ApiClient` to `RowanStaticHero.mount(root, ApiClient)` and call cleanup on route/user changes. No Home insertion, HSS `.sections` modification, File Transformation callback or live deployment is included. Do not replace Media Bar Enhanced until Home parity and A/B checks pass.

Parity gaps: no timed progress, swipe, keyboard/remote slide controls, item detail action, per-library hero configuration or equivalent full Media Bar settings. Previous/Next buttons and a slide count are present; trailers/video are intentionally excluded.

## Verification status

The earlier gated build was tested in a fresh disposable Jellyfin 12.1 container with two disjoint movie libraries and user policies: own image 200 JPEG, cross-user 404, anonymous 401 and userless API key 403. The atomic prototype subsequently passed a separate two-user disposable check (own JPEG 200, cross 404, anonymous 401, userless key 403, metadata symlink 404, media-outside-root 404). The no-cross-mount behavior passed a unit test against the existing `/dev/shm` mount beneath `/dev` and a populated disposable Jellyfin 12.1 HTTP check: a nested read-only file bind mount at the metadata backdrop returned 404, while the same image without that mount returned 200 JPEG. This was not a complete two-user HTTP rerun of the mounted revision. No live server was changed or enabled; the filesystem trust assumption remains unverified.
