# Featured still-image hero

## Trust and enablement

Both `HomeEnabled` and the separate `HeroTrustedFilesystemEnabled` admin setting must be true. Both default **off**. `HeroLibraryIds` must also contain explicitly selected stable collection-folder IDs; null, empty, malformed and duplicate selections yield no slides, never all libraries. The configuration key retains its name for compatibility; it now asserts trust in Jellyfin's **internal metadata**, not all media files. With the hero gate off, `GET Rowan/Home/Hero` returns `[]` for a valid user and `GET Rowan/Home/Hero/Image/{itemId}` returns 404 for a valid user; authorization still applies. The image route only accepts files under `IServerApplicationPaths.InternalMetadataPath/library`; media/share image paths fail closed. Do not enable the trust setting on a live server until metadata ownership, mount targets and write access are audited. Atomic confinement rejects symlinks and nested mounts, but the checkbox still asserts a trusted metadata source: malicious in-place writers and hardlinks inside that filesystem remain outside its protection.

`GET Rowan/Home/Hero` is `[Authorize]`, requires exactly one valid existing `Jellyfin-UserId`, and has no caller-supplied user/library IDs. It derives visible top-level collection folders from that user, queries at most 20 folders and 20 latest Movie/Series candidates per folder, checks the parent and ancestry again after the query (Jellyfin's missing-parent fallback), and performs DTO conversion with visibility checks enabled. The result is at most 10 slides, deterministically shuffled per user per UTC day. It contains item IDs, title, overview, year and a Backdrop image identity only—no arbitrary image URLs, trailers, playback URLs, paths or user data. At most 20 selected libraries are considered. Only the intersection of configured IDs and that user's visible folders is queried.

## Image route and limitations

`GET Rowan/Home/Hero/Image/{itemId}?tag=<hex>` is `[Authorize]` and requires exactly one real, existing `Jellyfin-UserId`; userless API keys are rejected. Every request re-resolves the item under Jellyfin's user-aware visibility lookup, checks parental/standalone visibility and ancestry against the user's currently visible **selected** collection folders, restricts kind to Movie/Series, and validates the current local Backdrop/0 image tag. It does **not** use `IImageProcessor` or resize: on Linux x86-64/arm64 it opens the exact absolute metadata path with `openat2` relative to a descriptor for `InternalMetadataPath/library`, using `RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS|RESOLVE_NO_XDEV` on the candidate, then checks type/size on that descriptor with `statx(AT_EMPTY_PATH)`. It reads at most 8 MiB, checks JPEG markers and dimensions (at most 8,294,400 pixels), and serves JPEG bytes without a redirect or path disclosure. Admission is limited to four concurrent distinct users, four requests per user per second and 16 globally per second; async reads have a three-second deadline. Responses have `private, no-store` and `nosniff`. Unsupported kernels/architectures, nonlocal, oversized, mount-crossing or unsupported images fail closed. The kernel confinement removes pathname symlink-swap TOCTOU for this route; it does not defend against malicious hardlinks or in-place mutation by writers inside the metadata filesystem.

The client uses authorized `ApiClient.fetch`, makes a short-lived blob URL from a JPEG response, revokes it on slide changes/teardown and ignores late responses or session changes. It never requests `/Items/{id}/Images/*` itself. Tags are cache identity, not access grants. **Jellyfin's separate raw image API can return HTTP 200 anonymously by item ID on v12.1**; this proxy protects only its own route, not that upstream API. Item IDs are not secrets.

The standalone `static-hero.js`/`.css` assets remain embedded and gated by Home/hero configuration. A Home-enabled installation with trusted, explicitly selected hero libraries can now mount the hero **without enabling Discovery**: it adds no empty Fin tab or Discovery HTML/JS/CSS. When Discovery is enabled, the Home/3pic Fin inner switch remains and Discovery data stays lazy. The host supplies a dedicated root, a signed-in API client, prefetched validated slides and a host-owned `openItem(id)` callback to `RowanStaticHero.mount(root, api, options)`. It loads these assets only after a nonempty authenticated Home response, and calls cleanup on Fin selection, route/user changes and teardown. The adapter provides `getCurrentUserId`, `accessToken`, `getUrl`, `getJSON` and authenticated `fetch`. Standalone callers may still pass `api.openItem`; the automatic host always overrides it with its own callback and revalidates the item through the user-scoped Jellyfin lookup before using `Emby.Page.showItem`. Without a callback the Open control is hidden. Do not construct a URL from the item name or allow the hero to navigate directly. HSS `.sections` remains in place. Production File Transformation and web-distribution pins are still unset; no live deployment is included. Do not replace Media Bar Enhanced until Home parity and A/B checks pass.

Focused Left/Right keyboard navigation, single-finger horizontal swipes, stable-focus pagination with 44px targets, previous/next buttons and a host-routed Open action are available. A single-slide hero hides inactive carousel controls. Autoplay uses monotonic wall time for 12-second intervals, pausing independently on hover, focus, hidden document or reduced-motion preference. Only the active slide image is fetched. Trailers/video and equivalent full Media Bar settings are intentionally excluded. Mounted Chromium proof at 360px and 1280px uses locally generated JPEG bytes returned through a stubbed signed-in API and verifies the decoded image and screenshot pixels; it is not a Jellyfin Home host or live-library proof. Run `python3 tests/Rowan.Jellyfin.Plugin.Tests/static-hero-controls.browser.py` to regenerate scratch screenshots.

## Verification status

A disposable Jellyfin 12.1 two-user HTTP probe (`python3 tests/disposable-static-hero.py`) now checks explicitly selected libraries, each user's slide and JPEG, cross-user and restricted-ancestor denial, anonymous 401, userless-key 403, empty/duplicate/switched selections, metadata-backed image confinement and symlink rejection. The rated-parent fixture's child lookup itself changed from 200 to 404 in Jellyfin; targeted policy tests additionally require ancestor checks when a child DTO appears independently visible. A separate nested-bind-mount probe returned 404 for the mounted metadata backdrop and 200 after removing the mount. A disposable signed-in Jellyfin 12.1 clone of the intended web distribution subsequently proved automatic Home mounting with a metadata-backed synthetic JPEG, native Open navigation, HSS scroll, Favorites, Fin switch, logout and a second-user login. It made one list and one image request on initial mount, with six of each across the full navigation sequence per browser case; all tested hero responses were 200. Three direct-width cases (390/768/1100px) passed; direct 320px and all four strict `/jellyfin/` prefix cases failed clone-wide acceptance because of HSS card overflow and dependency-plugin root-absolute assets, respectively. That hosted probe did not load ElegantFin; live household performance remains untested. Gill was neither enabled nor changed, and the metadata-writer trust decision is still open.

The separate `static-hero-elegant.browser.py` fixture renders the real hero JS/CSS under both captured ElegantFin stylesheets (SHA-256 pinned in the test), with an original JPEG and a synthetic Home row. Set `ELEGANTFIN_CSS_DIR` to a directory containing `elegant-source-0.css` and `elegant-source-1.css`, then run `python3 tests/Rowan.Jellyfin.Plugin.Tests/static-hero-elegant.browser.py`; optional `HERO_SCREENSHOT_DIR` collects screenshots outside the repository. At 3680, 1280 and 390px it checks the shared title/counter/pagination/progress/Open gutter, reserved row and hero positions before/after delayed slide and image delivery, horizontal overflow, ultrawide one-line heading, dot touch targets, keyboard focus, arrows and computed single-slide control visibility. This is a captured-theme DOM regression, **not** proof of signed-in hosted ElegantFin integration or first-paint CLS before the host reserves the slot.
