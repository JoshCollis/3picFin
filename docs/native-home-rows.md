# Native Home rows — staged replacement slice

## Supplementary Home integration

This branch adds a sibling `.rowan-native-rows` after Jellyfin Home's direct `.sections` child. It does not move or replace core Home sections. The existing Home adapter supplies the 12.1 structural/version/route/identity gate; the host owns hero, Fin switch, row styles, lifecycle and native Open bridge. It clears row DOM on Fin selection, Favorites/route exit, logout and account switch; delayed replies and Open rechecks are generation/user guarded. Rows are lazy per viewport intersection, capped to nine configured kinds and 64 cards per ordinary row (five groups × 16 for Because You Watched). Images use tagged Jellyfin item paths through `ApiClient.getUrl`; cards without art retain text. Native Open re-reads the currently signed-in user's item and checks ID/type before `Emby.Page.showItem`.

Configuration is **server-side XML/API only for this branch** (the independent admin UI branch owns form changes). Set `HomeEnabled=true`, `NativeHomeRowsEnabled=true`, and an explicit ordered `NativeHomeRowKinds` array. Empty/null selection renders nothing. Supported personal rows: `ContinueWatching`, `NextUp`, `LatestMovies`, `LatestShows`, `MyMedia`; optional `ContinueWatchingNextUp`, `Collections`, `BecauseYouWatched`, `MyRequests` also require their existing independent enabled flags. `MyRequests` additionally needs Seerr and includes only the user's locally available requested items. Unknown/duplicate names are filtered. Household-wide Arr upcoming rows, Live TV, Seerr Discover candidate rows and shared requests are deliberately **not** mounted by this replacement: their data or navigation is not interchangeable with personal playable Jellyfin cards. No cross-library shared data is turned on by default. The backend remains responsible for each user's entitlement and parental ancestor checks; the browser is not an authorization boundary.

**Unimplemented HSS parity:** HSS's broad row catalog and arbitrary ordering/settings, carousel controls, watched/window/rewatch preferences beyond existing backend flags, TV remote/play button/progress treatments, library folder native navigation, populated Live TV/guide playback, HSS-style upcoming/discover art and interactions, HSS My Requests semantics comparison, and verified HSS performance equivalence. Core Home remains visible, so a selected supplementary row may duplicate a native row. The admin form does not yet edit these two settings. No HSS code or assets were copied.

Proof in this branch: browser generated-DOM test at 320/1280 px with populated title/tagged art, lazy second row, fresh native Open, Home↔Fin, simultaneous hero and rows, Favorites unchanged, direct-child `.sections` preserved, and teardown/user switch. Separate renderer test checks two recommendation groups and proportions. When the customized MUI toolbar/drawer is absent, the host now places an accessible Fin action immediately after the structurally validated two-button native Home/Favorites tabs—not inside the managed slider. The 320/1280 px toolbar-free fixture checks this fallback; malformed or ambiguous native tabs still fail closed. This is a **synthetic stock-style DOM**, not an unchanged signed-in stock Jellyfin 12.1 installation or any-Jellyfin portability proof. The runtime also requires the 12.1 version/resource-timing, route, active pane, and user gates; a different header/tab structure gets no Fin action. No disposable server was started for this slice. Before enabling on a household server, test the unchanged Release DLL on stock 12.1 and the target clone with real users, images, scrolling, Favorites, subpath, logout, user switch, and core row preservation. Do not claim visual HSS parity or a speed improvement from the fixture.

## Historical endpoint work (below)

The remainder records earlier backend proof; its statements that the renderer is isolated/not mounted refer to the earlier slice, not this integration.

Source review: Jellyfin 12.1.0 `ItemsController.GetResumeItems`, `TvShowsController.GetNextUp`, `TVSeriesManager.GetNextUp`; HSS 3.0.2 `ContinueWatchingSection`, `NextUpSection`, `ContinueWatchingNextUpSection`, `LatestSectionBase`, `LatestShowsSection`, `MyMediaSection`, and `loadSections.js`. This is a partial Home inventory, not an assertion of equivalent UX. HSS remains active; no `.sections` mutation or live deployment.

`GET Rowan/Home/Rows/{kind}` accepts exactly seven row names, no `userId`/`parentId` or caller-specified limit. Requires one real `Jellyfin-UserId` claim and an existing user, and `HomeEnabled`; returns private/no-store responses. The server uses Jellyfin's own resumable and Next Up queries rather than reconstructing watch state, and user-scoped library queries for premiere-date rows. Every candidate is intersected with current visible-library ancestry **and** checked with `IsVisibleStandalone(user)` before DTO conversion: Jellyfin 12.1 DTO conversion only calls `IsVisible(user)` and does not check a restricted parent series. Latest Movies/Shows paginate at most eight 32-item pages per visible matching library to refill after filtering; Latest Shows drops future episodes, allows same-local-day episodes only when a timezone-qualified, non-midnight premiere timestamp has elapsed, and fails closed for same-day date-only or timezone-unknown values (air time cannot be established). It ranks each series by its newest eligible episode across visible libraries, then resolves the user-visible series for DTO output. Next Up applies the same air-time gate and also rejects virtual episodes. My Media retains synthetic user-specific views via `DisplayParentId` and grouped movie/TV views only when the user has grouped a currently visible matching library. The bounded cap can truncate extremely duplicate-heavy libraries. Per-request rows and the opt-in `native-home-rows.js` adapter support viewport lazy loading with independent error states and user-switch teardown. The adapter renders text-only candidate cards in a **caller-owned isolated container**; it never touches HSS `.sections`, does not provide playback/navigation yet, and is not automatically injected into Home. The existing Home host remains unpinned and fail-closed.

## Live TV candidate (staged)

HSS 3.0.2 (`d9798e4`, `LiveTvSection`) calls `GetRecommendedProgramsAsync` with `IsAiring=true`, `Limit=24` and landscape cards. Jellyfin 12.1 (`ee91c75e`, `LiveTvManager`) expands that request to at least 200 program candidates before ranking; it does not explicitly intersect each recommendation with a user-scoped channel inventory. The Rowan route `GET Rowan/Home/Rows/LiveTV` derives one existing user from the claim, requires `HomeEnabled`, independent `LiveTvRowEnabled`, and `ILiveTvManager.IsEnabledForUser`. It reads at most eight 128-channel pages through `GetInternalChannels(UserId=user.Id)`, intersects recommendation `ChannelId` with those channel IDs, rechecks both channel and program `IsVisibleStandalone(user)`, current start/end dates and deduplicates programs. The resulting private/no-store JSON is a bounded `Kind`/`Items` allowlist: program/channel GUID, bounded names/number, start/end UTC. It includes **no** media source, playback URL, tuner identifier, or arbitrary user/channel/parent/limit parameter. A channel with no airing guide program produces no card; it is not represented as a stream. The isolated `native-home-rows.js` renderer requests this kind only with `enabledRows: ['LiveTV']`, uses text-only labels and disposes on user change. The IDs are navigation identity for a future trusted host, not a browser playback link.

Focused policy/controller and admin/Node tests plus complete .NET and Node suites pass. A disposable two-user Jellyfin 12.1 HTTP probe with **no tuner** verified exact route and PascalCase empty `Kind`/`Items` for both users, `private, no-store`, anonymous 401 and userless API-key 403; the container and scratch credentials were removed. A real tuner/guide was **not** provisioned for this slice; populated channel entitlement and actual navigation/playback remain runtime acceptance gates. HSS stays enabled; Home adapter pins remain null. The bounded 200-result recommendation source scans up to 800 candidates internally in Jellyfin 12.1 and may still underfill after entitlement filtering, and 1,024-channel inventory truncation can omit later channels; it never broadens entitlement to fill a row. Do not replace the HSS Live TV section from this staged preview.

## Verification / A-B design

Unit tests exercise missing/zero user claim, independent visible-library sets and a mixed foreign result, a simulated standalone parental veto, refill after filtering, distinct series, unaired exclusion, synthetic view mapping and row caps. A separate disposable `jellyfin/jellyfin:12.1` instance loaded this branch's Release DLL with Home enabled and two real users assigned disjoint movie/TV libraries. Each user's five row responses contained only their own resumable item, Next Up episode, recent movie/series and media views; neither user's foreign items appeared. A TV-MA series with TV-G child episodes remained inaccessible to a TV-G-limited user (`/Items/{child}` and `/Items/{series}` both 404), and the series was absent from Latest Shows despite 37 recent child episodes. The first 32-item admin episode page held 31 of those restricted episodes plus one future episode; Latest Shows paged past that page to retain the allowed series. A future allowed episode was excluded from Latest Shows, while the separate Jellyfin Next Up query **did return** that episode in the earlier disposable run. The native adapter now post-filters unaired and virtual Next Up episodes and refills bounded pages; this change has unit coverage but has **not** been rechecked against that disposable server. Two grouped movie libraries yielded a synthetic `Movies` UserView in My Media, with no foreign view. Temporarily revoking the user's TV library immediately emptied Next Up/Latest Shows and removed its My Media view; restoring the grant restored access. All five endpoints returned PascalCase JSON and `Cache-Control: private, no-store` for signed-in requests, 401 anonymously and 403 with a userless API key. This proves the endpoint behavior in a lab, **not** browser Home integration or HSS parity. Do not mistake endpoint 200 with an empty disabled Home for content success. The host's full `Authorization: MediaBrowser Client="…", Device="…", DeviceId="…", Version="…", Token="…"` form is required.

A disposable Jellyfin 12.1 HTTP probe of the staged ContinueWatchingNextUp and Collections rows used two users with disjoint movie/TV libraries. Each received only their own resume movie and Next Up episode, with Collections newest-first and foreign-only/rating-restricted boxes excluded. A box with both entitled and foreign members remained visible through each user's own entitled member. Rating the parent series R while its child remained G made Jellyfin return 404 for both to the limited user, and the combined row dropped the child. Both routes returned signed-in `private, no-store`, anonymous 401 and userless-key 403. The probe covered one collection folder only, not the cross-folder ordering fix, and did not exercise browser Home presentation; its temporary script was not part of this repository.

Before replacing HSS, use the **same media/user/session and browser** to compare HSS 3.0.2 vs native presentation over cold and warm runs: first usable Home content, per-row p50/p95 server latency, network request count/bytes, long tasks, scroll-to-row time and playback/navigation correctness. Separate plugin query time from browser paint and images; record sample counts, device and cache state. Validate row order, sections below fold, phone/TV navigation, Favorites, logout/user switch, HSS coexistence and revert. No performance improvement or complete parity is claimed from this branch.

Second slice: HSS 3.0.2 `ContinueWatchingNextUpSection` merges Resume (12) and Next Up (24), deduplicates on item ID, optionally excludes `UserData.Played`, then sorts by `UserData.LastPlayedDate`, latest played episode in each series, or `DateCreated`; `CollectionsSection` discovers boxsets libraries, sorts collections by `DateLastMediaAdded` and returns 16. The new routes preserve this source ordering contract with stricter entitlement checks and bounded pagination. `HomeEnabled` plus `CombinedPlaybackRowEnabled` or `CollectionsRowEnabled` must be set by the administrator to return these rows. The browser adapter only includes the two additional names when its caller passes `enabledRows: ['ContinueWatchingNextUp', 'Collections']` (or a subset); it never reads the server configuration itself. These routes have unit/Node and disposable two-user HTTP checks, but **no browser Home/HSS presentation parity check on this slice**. Keep HSS installed and the host integration disabled.
