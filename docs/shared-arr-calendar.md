# Shared Arr Calendar (staged, default off)

`CalendarEnabled` is independent of `DownloadsEnabled`; both use the same validated server-only Radarr/Sonarr URL/key fields. The admin setting explicitly discloses that **every existing signed-in Jellyfin user** can see calendar titles and episode labels even outside their own libraries or parental restrictions. Neither tracked status nor a release date establishes Jellyfin watchability. The nested Calendar view is wired into the 3pic Fin Discovery panel, loads on selection, and has Node UI coverage for navigation, partial/error states and teardown. Do not enable on Gill before signed-in real-Arr/browser acceptance and a decision about the household-wide policy.

`GET /3picFin/Calendar?start=YYYY-MM-DD&end=YYYY-MM-DD` accepts a half-open UTC window of at most 31 days. Anonymous callers return 401; userless/unknown/duplicate user claims return 403; invalid dates return 400; admission overflow returns 503. The response is `private, no-store`, with independent `Radarr` and `Sonarr` sources (`Items`, `Partial`, `Error`). When disabled/unconfigured, the source reports `Disabled`; malformed configuration reports `InvalidConfiguration`; other upstream failures report `UpstreamUnavailable` with no upstream text. No errors contain server URLs or keys.

The pinned Radarr 6.4.4.10685 route is `/api/v3/calendar?start=…&end=…&unmonitored=false`; each movie locally expands `inCinemas`, `digitalRelease`, `physicalRelease` within the window as Cinema/Digital/Physical. The pinned Sonarr 4.0.20.3014 route is `/api/v3/calendar?start=…&end=…&unmonitored=false&includeSeries=true&includeEpisodeFile=false&includeEpisodeImages=false`; `airDateUtc` is locally filtered within the same UTC window and duplicate episodes collapse. Responses are bounded to 128 KiB per source; at most 100 locally validated records per source are processed, and larger valid arrays produce a marked partial result rather than dropping the source. Output contains only source, media type, external title ID, truncated title, event type, UTC date, and for episodes season/episode numbers and truncated episode title. No paths, filenames, queue metadata, ownership, file presence, or per-request attribution are sent. Requests have separate Calendar admission (four global, one per user), independent eight-second deadlines for Radarr and Sonarr, and disabled redirect following.

Disposable Jellyfin 12.1 HTTP verification with stub Arr sources passed for two users with disjoint library views: both received identical Cinema/Digital/Physical and Sonarr episode DTOs in the same 31-day window. Anonymous returned 401, userless API key 403, invalid windows 400, and responses were `private, no-store` with no stubbed path or key. Malformed Radarr kept Sonarr available, failed Sonarr kept Radarr available, and 101 Radarr records yielded a capped partial result. Throwaway containers and generated credentials were removed. This proves the staged HTTP route with stubs; the separate Node UI tests prove nested browser behavior with stubbed responses. Neither proves live Arr data or a signed-in production Calendar view; keep the live switch off until those gates pass.
